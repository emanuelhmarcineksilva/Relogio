 NOVIDADES IMPLEMENTADAS
═══════════════════════════════════════════════════════════════════════════════

✓ COMPONENTE NOVO: LCD 16x2 com I2C
  └─ Endereço: 0x27 (mesmo barramento I2C do OLED e RTC)
  └─ Atualização: A cada 1 segundo, totalmente não-bloqueante
  └─ Layout:
     * Linha 1: HH:MM | Temperatura
     * Linha 2: IP/AP | Símbolo [Sol|Nuvem|Chuva|Frio]

✓ DETECÇÃO AUTOMÁTICA DO SÍMBOLO CLIMÁTICO
  └─ Baseado em temperatura LOCAL (DHT22):
     * [Sol]   = T > 25°C
     * [Nuvem] = 14°C ≤ T ≤ 25°C
     * [Frio]  = T < 14°C
  
  └─ Baseado em descrição da API (OpenWeatherMap):
     * [Chuva] = se description contém: "chuva", "rain", "chuvisco", "drizzle"

✓ MELHORIA: Extração de dados climáticos mais completa
  └─ Antes: apenas temperatura
  └─ Depois: temperatura + descrição textual (JSON: weather[0].description)
  └─ Permite detectar chuva automaticamente

✓ PERFORMANCE: Atualização não-bloqueante do LCD
  └─ Verificação de intervalo: if (agora - ultimaAtualizacaoLCD < 1000) return;
  └─ Permite ~1000 ciclos do loop entre atualizações
  └─ Sem impacto significativo na responsividade do sistema

 IMPACTO DE PERFORMANCE
═══════════════════════════════════════════════════════════════════════════════

Ciclos do loop principal:
  Antes: ~1000 ciclos/segundo
  Depois: ~1000 ciclos/segundo (SEM ALTERAÇÃO)
  
Tempo gasto com LCD (por ciclo):
  ├─ 999 ciclos: ~0 μs (apenas verificação de tempo)
  └─ 1 ciclo: ~5-10 ms (escrita real no I2C)
  
Média por segundo: (999 × 0 + 1 × 7.5) / 1000 = ~7.5 ms = 0.75% da CPU

Memória:
  └─ RAM adicional: ~100 bytes (variáveis de estado)
  └─ Flash adicional: ~2-3 KB (novas funções)

├─ Wire.begin(SDA=21, SCL=22)
├─ Velocidade padrão: 100 kHz

═══════════════════════════════════════════════════════════════════════════════
 NOTAS ADICIONAIS
═══════════════════════════════════════════════════════════════════════════════

1. O LCD atualiza A CADA 1 SEGUNDO, não em tempo real.
   Isso é intencional para economizar CPU e não prejudicar a responsividade.

2. O símbolo climático é baseado PRINCIPALMENTE em temperatura LOCAL (DHT22).
   A descrição da API é usada APENAS para detectar chuva (override).

3. Se a API de clima falhar, o símbolo continua sendo exibido
   com base apenas na temperatura local.

4. O barramento I2C é compartilhado:
   - OLED: 0x3C (128x64, menu)
   - LCD: 0x27 (16x2, informativo)
   - RTC: 0x68 (hora)
   - Todos no mesmo SDA/SCL (GPIO21/GPIO22)

5. O menu OLED continua 100% funcional. O LCD é apenas um
   painel de informações complementar.
